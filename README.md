## 项目背景
通过ssh到另一台linux设备开发

本项目目标是在地面站侧提供一个可执行、可观测、可恢复的双机任务控制前端，替代当前“人工 SSH + 手工回车 + 遥控器介入”的主流程，降低实机操作复杂度。

## 已确认约束（必须遵守）
1. 前端运行位置：地面站 Linux 环境。
2. 地图显示需求：不做自定义渲染，仅拉起 RViz 外部窗口显示栅格地图。
3. 起飞与降落策略：顺序执行可接受（不要求严格同步）。

## 实际系统现状
1. 双机（NUC/Fly）各自搭载机载电脑，分别运行飞控、建图、控制、探索相关 ROS 节点。
2. 当前通过 Windows 电脑 SSH 到两台机载电脑，分别执行所需命令
3. 地面站负责接收数据并显示建图结果。
4. 现有流程具备可用性，但人工步骤多、状态不可视、失败恢复慢。

## 前端目标
构建一个运行在地面站 Linux 的前端控制系统，覆盖以下核心能力：
1. 一键启动双机任务链（自动 SSH 到 NUC/Fly 并执行对应启动脚本）。
2. 顺序起飞控制（先 1 号机，后 2 号机，具备状态检查和超时处理）。
3. 顺序降落控制（先 1 号机，后 2 号机，支持异常中止和安全兜底）。
4. 一键拉起 RViz（加载固定 .rviz 配置）显示栅格地图与必要状态图层。
5. 提供统一日志与失败提示，便于现场排障。

## 范围定义

### In Scope（本期必须实现）
1. 双机 SSH 连通性检测与一键远程启动。
2. 前端按钮触发起飞/降落流程（顺序执行）。
3. RViz 窗口一键拉起（使用固定配置文件显示栅格地图）。
4. 双机基础状态面板（在线、模式、解锁、任务阶段）。
5. 操作日志窗口（时间戳 + 节点 + 结果）。

### Out of Scope（本期不做）
1. 前端内嵌地图渲染（QGraphicsView、Matplotlib、WebGL 等）。
2. RViz 三维点云高性能渲染优化。
3. 双机严格毫秒级同步控制。
4. 复杂任务编排器（工作流可视化拖拽、策略编排 DSL）。
5. 自动改写飞控参数与系统级网络配置。

## 建议架构（地面站侧）
1. UI 层：前端界面（按钮、状态面板、日志窗口）。
2. 控制层：任务编排服务（Start、Takeoff、Land、Stop、Status）。
3. 通信层：
   - SSH 客户端：远程执行 OpenSSH 命令，并通过 tmux 在远端直接创建/重建会话、窗口与任务序列。
   - ROS 接口：订阅状态、发布控制命令。
   - 降落触发方式：由地面站按钮发起任务级降落请求，控制层再通过 ROS/MAVROS 转成飞控可执行指令，不再依赖遥控器通道直接触发。
4. 可视化层：RViz 外部进程管理（启动、关闭、状态检查）。
5. 观测层：结构化日志 + 告警提示 + 简单重试机制。

## 技术路线（建议落地方案）

### 技术选型
1. 前端界面：Qt5/PySide6（Linux 原生桌面应用）。
   - 理由：与 ROS1 Python 生态集成直接，部署简单，现场可维护性高。
2. 控制后端：Python 服务层（与前端同进程或子进程）。
   - 职责：封装 SSH 控制、任务状态机、超时重试、日志聚合。
3. ROS 通信：rospy + 独立订阅线程。
   - 订阅：双机状态话题。
   - 发布/调用：起飞、降落、中止相关控制接口。
   - 交互原则：UI 只负责发起“起飞/降落/中止”等任务请求，ROS 控制节点负责把请求落到 /mavros/set_mode、/mavros/cmd/arming 等具体飞控接口。
4. 远程执行：OpenSSH（优先密钥认证）+ tmux 会话编排。
   - 前端直接在远端创建/重建 tmux session，按窗口 1-9 组织任务。
   - 窗口 1-7 自动启动；窗口 8-9 预置命令，等待手动触发。
   - 基础链路阶段采用固定等待节奏，便于现场排障与观察输出。
5. 地图显示策略：不做自定义渲染，只由前端拉起 RViz。
   - 命令示例：rviz -d /home/hua/uav_front_end/config/map_only.rviz。
   - 前端职责：仅管理 RViz 进程生命周期（启动/关闭/存活检测）。

### 版本规划
1. V1（最小可用）
   - 一键 SSH 启动双机脚本。
   - 状态面板（连接、模式、解锁）。
   - 一键顺序起飞、一键顺序降落。
   - RViz 一键打开（固定配置）。
   - 日志窗口与失败提示。
2. V2（增强可观测）
   - 流程超时重试与中止策略完善。
   - 操作日志导出。
3. V3（工程化）
   - 配置管理（双机 IP、端口、超时、重试次数、RViz 配置路径）。
   - 健康检查面板（节点存活、话题频率、链路质量）。

### 模块拆分
1. ui_app.py
   - UI 事件处理、按钮状态切换、日志展示、RViz 控制按钮。
2. mission_orchestrator.py
   - 启动/起飞/降落/中止状态机与顺序控制，负责远端 tmux 会话与窗口编排。
3. ssh_executor.py
   - SSH 连通性检测、远程命令执行、错误码处理。
4. ros_adapter.py
   - 统一订阅状态、发布控制。
5. rviz_manager.py 
   - RViz 进程启动、关闭、重复拉起保护、异常退出检测。
6. settings.yaml
   - 双机连接参数、流程超时与重试策略、RViz 配置路径。

### 推荐实施顺序
1. 先打通 SSH 一键启动与状态回读。
2. 再实现顺序起飞/降落控制状态机。
3. 接入 RViz 外部拉起与进程管理。
4. 每步完成后进行实机回归，确保不影响现有可用流程。

## 关键流程（顺序执行）

### 1) 一键启动流程
1. 检查 SSH 连通性（NUC/Fly）。
2. 远程执行启动脚本（分别触发 nuc.py start 与 fly.py start）。
3. 轮询关键 ROS 节点/话题是否就绪。
4. 前端标记“系统就绪/部分失败/整体失败”。

### 2) 一键起飞流程（顺序）
1. 飞机 A 进入 OFFBOARD、解锁、起飞到安全高度。
2. 飞机 A 达到稳定状态后，飞机 B 执行同流程。
3. 两机均稳定后，进入探索阶段。

### 3) 一键降落流程（顺序）
1. 飞机 A 在地面站点击“降落”后，由控制层发起降落请求并监测落地/上锁。
2. 飞机 A 完成后，飞机 B 执行降落。
3. 两机降落完成后结束任务并归档日志。

### 4) 地图显示流程（RViz 外部窗口）
1. 点击“打开地图”按钮。
2. 前端启动 RViz 并加载固定配置文件。
3. 若 RViz 已在运行，前端不重复启动并给出提示。
4. 点击“关闭地图”按钮时，前端结束 RViz 进程。

## 异常处理要求
1. 任一步骤超时必须可见（UI 提示 + 日志记录）。
2. 若飞机 A 失败，默认不自动继续飞机 B（避免扩大风险）。
3. 提供“中止任务”按钮，触发安全停机/降落兜底策略。
4. 网络短时抖动允许有限次数重试，重试失败需人工确认。
5. RViz 启动失败（配置缺失/显示环境异常）需给出明确错误提示。
6. 降落指令必须走任务编排链路，不允许 UI 直接模拟遥控器通道作为主控制手段。

## 数据与接口约定（待实现时细化）
1. 输入：
   - 双机连接配置（IP、用户名、密钥路径/端口）。
   - 起飞高度、超时参数、重试次数。
   - RViz 配置文件路径。
2. 输出：
   - 双机状态流（连接、模式、armed、高度简要信息）。
   - RViz 进程状态（运行中/未运行/异常退出）。
   - 任务执行日志（可检索、可导出）。

## 验收标准（DoD）
1. 在地面站 Linux 上，单击一次“启动”可完成双机远程脚本触发并给出明确结果。
2. 在网络正常情况下，单击一次“起飞”可按顺序完成两机起飞，且状态面板正确更新。
3. 单击一次“降落”可按顺序完成两机降落，最终均进入安全结束状态。
4. 单击“打开地图”可启动 RViz 并显示预设地图视图；单击“关闭地图”可结束 RViz。
5. 任一失败路径都有日志证据与可执行的下一步提示。

## 开发约束
1. 优先复用现有启动脚本，不推翻当前可用流程。
2. 地图显示固定采用“外部 RViz 拉起”策略，不实现内嵌渲染。
3. 不在本期引入 GPU 依赖链。
4. 不在本期实现高风险自动化动作（如无保护的强制解锁/强制模式切换）。
5. 所有控制动作都必须有前置检查、超时和失败回滚策略。
